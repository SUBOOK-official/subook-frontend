프로젝트 개요

수북은 판매자가 맡긴 수능 교재를 수거·검수하고 구매자에게 판매한 뒤 판매자에게 정산하는 중개 서비스다. QA는 상품을 고르는 화면만으로 검증 범위를 제한하지 않았다. 동일 교재의 개별 재고, 카드 인증과 주문 생성의 순서, 부분환불, 과거 수거 건의 수수료 정책까지 하나의 거래 흐름으로 다뤘다.

테스트 전략

P0는 잘못된 청구·재고 판매·정산·권한 노출을 막는 테스트다. 하나라도 실패하거나 실행이 막히면 출시를 중단한다. P1은 정상 거래와 주요 복구 흐름, P2는 사용성·호환성, P3는 기능이 유지되는 표시 개선이다. TC 우선순위와 결함 심각도는 별도 필드로 관리했다.

진입 기준

• 검증 빌드와 정책 기준이 고정되고, 이전 빌드와 변경점이 공유되어야 한다.

• 합성 회원·교재·수거·주문 데이터를 초기화할 수 있어야 한다.

• PG·알림·DB를 실제 연동하는 테스트와 fixture 테스트의 대상이 구분되어야 한다.

• P0 시나리오에 필요한 데이터나 접근 권한이 없으면 Blocked로 기록한다.

종료 기준

• P0 전부 통과, 미종결 S1·S2 0건, Blocked 0건.

• 실패한 TC는 수정 빌드에서 다시 실행하고 관련 회귀도 통과해야 한다.

• Deferred는 영향·우회 방법·후속 담당 역할·재검증 조건을 기록한다.

• 부하 판정에는 요청 수, 측정 구간, 워밍업, 오류율, p95와 측정 범위를 함께 적는다.

도구 선택과 담당 업무

Selenium은 수북 웹의 반복 구매·인증 흐름에 적용했다. Page Object에 화면 선택자를 모으고, 임의 sleep 대신 표시·활성화·URL 조건을 기다렸다. 테스트마다 새 Chrome 세션과 장바구니를 사용하고 성공·실패 화면을 모두 남겼다. 480px 검증은 모바일 웹 레이아웃 검증으로 정의했다.

Postman은 정상 응답뿐 아니라 오류 코드, 추가 호출 유무, 보상 호출 순서를 검증하는 데 사용했다. Collection을 Newman으로 실행하고 JSON·JUnit 결과를 남겼다. 예를 들어 '이미 결제 완료' 응답에는 PG 재승인이 없어야 하며, 자동취소까지 실패하면 주문 해제 대신 운영 경보가 있어야 한다.

JMeter는 1·10·25명의 동시 사용자, ramp-up, 요청 간격, 혼합 비율을 설정했다. API 오류 응답이 기대 결과인 경우 HTTP 401·303 자체를 실패로 세지 않고 assertion으로 판정했다. 워밍업을 제외한 측정과 전체 dashboard를 구분했다.

공고의 Appium·UIAutomator는 네이티브 앱 자동화 확장 시 선택할 도구로 남겼다. 이 포트폴리오의 구현 범위는 수북 웹과 서버 API다.

절차: 정상 문의를 보낸다. 첫 응답 실패를 주입한다. 두 번의 referenceId와 큐 레코드를 비교한다.

기대: 동일 참조번호를 재사용하고 DB 중복 방어로 접수1건이다. 실제: 재시도 루프에서 새 번호가 발급되어 운영 문의가 두 건으로 들어왔다.

분석·조치: 참조번호 생성을 재시도 바깥으로 이동하고 참조번호별 멱등 처리를 확인했다.

처리 이력: W5 D1 New, W5 D2 Resolved, W5 D2 Retest→Closed. 503→200, 503→503, 403(재시도 없음)을 확인했다. 현재 로컬 자동화는 재시도 호출과 참조번호 보존을 검증하며 실제 DB 큐 중복 방지는 통합 검증 범위다.

QA-BUG-008 15MiB를 1byte 초과한 파일이 15.0MB로 안내됨

• 발견: W5 D3 / QA-S05-b3 / 관리자 이미지 업로드

• 데이터: PNG 메타데이터15728641bytes, 상한15728640bytes

• 재현율: 3/3. 관련: TC-029·030, 기존 IMG 경계 자동화.

절차: 초과 파일을 선택한다. 업로드 차단 여부와 오류 문구의 현재 용량을 확인한다.

기대: 제한을 초과했음을 이해할 수 있는 표기다. 실제: 업로드는 정상 차단되지만 현재 크기15.0MB가 제한15MB와 같아 보였다.

분석: 현재 용량을 소수 첫째 자리로 반올림했다. 대안: 초과 안내에서는 올림·추가 자릿수·byte 표기 중 하나로 경계를 설명한다.

처리 이력: W5 D3 New→Triaged, W6 D1 Deferred. 기능적 차단과 데이터 보호는 정상이고 운영자가 더 작은 파일을 사용할 수 있어 후속 릴리스로 이관했다. 후속 담당 FE, 재검증 조건은 상한±1byte와 일반 대용량 파일의 안내 문구 확인이다. Closed로 집계하지 않는다.

# 수북 버그 리포트

**가상 QA 수행 시나리오의 결함 대장.** 아래 빌드·발견·수정·재검증 기록은 프로젝트 설정이며 실제 운영 장애 이력이 아니다. SIM 접두사로 현재 발견 결함과 분리했다.

## 분류와 처리 규칙

S1 Critical은 청구·재고·정산의 손실 가능성, S2 Major는 주요 기능 실패, S3 Minor는 우회 가능한 기능 문제, S4 Trivial은 표시 문제다. P0는 출시 전 필수 조치, P1은 현재 회차, P2·P3는 영향과 일정에 따라 처리한다. 상태는 New → Triaged → In Progress → Resolved → Retest → Closed이며 재현되면 Reopened로 돌린다. Deferred는 수용 근거와 후속 조건을 남긴다.

## SIM-BUG-001 재고 2권 옵션에서 3권 선택 가능

- 발견: W3 D1 / QA-S03-b1 / Chrome 데스크톱, 480px 웹
- 환경·데이터: 상품900000, 옵션7, 개별 교재900001·900002, 각6000원
- 재현율: 설정 5/5. 회귀: SEL-02.

**절차**: 상품 상세에서 옵션7을 선택한다. 같은 옵션을 두 번 더 선택한다. 선택 수량·합계·증량 버튼을 확인한다.

**기대**: 재고2권에서 더 증가하지 않고 12000원이며 증량 버튼이 비활성이다. **실제**: 수량3, 18000원이 표시되고 주문 단계에서 재고 부족 오류가 발생했다.

**영향**: 구매자가 결제 직전에 수량을 다시 조정해야 한다. 서버 재고 검증이 있어도 화면의 구매 가능 수량이 잘못 안내된다.

**분석·조치**: 옵션 그룹 수량과 증량 허용 조건이 따로 계산되었다. 그룹 가용 권수를 기준으로 옵션 재선택과 + 버튼에 같은 상한을 적용했다.

**처리 이력**: W3 D1 New→Triaged, W3 D2 Resolved(QA-S03-b2), W3 D2 Retest→Closed. 재고0·1·2 및 선택 삭제 후 재선택을 재검증했다. 설정상 결과는 모두 Pass.

## SIM-BUG-002 같은 옵션 2권을 담아도 한 권의 ID가 중복 전달됨

- 발견: W3 D2 / QA-S03-b2 / Chrome
- 데이터: 옵션7 교재900001·900002, 옵션10 교재900003
- 재현율: 설정 3/3. 회귀: SEL-03·04.

**절차**: 옵션7 두 권과 옵션10 한 권을 선택한다. 장바구니에 담는다. 전송한 book_id 목록과 장바구니·주문서 수량을 비교한다.

**기대**: [900001,900002,900003]이 각 한 번 전달되고 총3권이다. **실제**: [900001,900001,900003]이 전달되어 한 권이 누락되거나 중복 오류가 났다.

**영향**: 화면 합계와 실제 구매 대상이 달라진다. **분석·조치**: 옵션 대표 ID를 수량만큼 복제하던 부분을 개별 재고 ID 할당으로 변경했다.

**처리 이력**: W3 D2 New, W3 D3 Resolved, W3 D3 Reopened(삭제 후 재선택에서 다시 중복), W3 D4 재수정, W3 D4 Retest→Closed. 최초 경로뿐 아니라 삭제·재선택과 주문서까지 확인했다.

## SIM-BUG-003 상품금액이 정확히 50000원일 때 배송비 3000원 부과

- 발견: W4 D1 / QA-S04-b1 / 주문서
- 데이터: 상품합계49999·50000·50001, 쿠폰·포인트 미사용
- 재현율: 설정 3/3(50000원 조건). 회귀: TC-014 경계값 묶음.

**절차**: 각 상품합계로 주문서에 진입한다. 배송비와 총액을 확인한다.

**기대**: 배송비는 3000·0·0, 총액은 52999·50000·50001원이다. **실제**: 50000원 주문에도 배송비3000원이 붙어 총53000원이었다.

**분석·조치**: 무료배송 조건의 `>`를 정책에 맞는 `>=`로 통일했다. 화면과 주문 생성 계산 경계를 함께 점검했다.

**처리 이력**: W4 D1 New→Triaged, W4 D2 Resolved(QA-S04-b2), W4 D2 Retest→Closed. 할인 정책은 별도 조건으로 분리하고 상품합계 경계 세 건을 재검증했다.

## SIM-BUG-004 카드 인증 전에 창을 닫아도 주문과 재고 선점이 남음

- 발견: W4 D1 / QA-S04-b1 / 카드 결제
- 데이터: 재고1권 상품, 구매자A·B, 미인증 결제 세션
- 재현율: 설정 5/5. 회귀: TC-017 및 API-PAY-01, 실제 DB 확인은 별도 통합 항목.

**절차**: A가 주문서에서 카드 결제창을 연다. 카드 인증 전 창을 닫는다. A의 주문 목록과 B의 상품 구매 가능 상태를 확인한다.

**기대**: 중단된 인증으로 신규 주문·재고 선점이 남지 않아 B가 구매할 수 있다. **실제**: A에게 입금대기 주문이 남고 B에게 품절로 노출되었다.

**영향**: 실제 결제가 없는 구매 시도로 판매가 차단된다. 출시 차단 P0로 판정했다.

**분석·조치**: 결제창 진입 시 주문을 먼저 생성했다. 인증 전에는 결제 세션만 만들고 서명 검증 후 주문을 실체화하도록 변경했다. 인증 실패, 세션 만료, 중복 복귀의 경로도 함께 분리했다.

**처리 이력**: W4 D1 New→P0 triage, W4 D2 In Progress, W4 D3 Resolved(QA-S04-b3), W4 D3 Retest→Closed. 중단 후 주문0·재고 유지·타 회원 구매 가능 및 정상 승인 흐름을 재확인했다.

## SIM-BUG-005 회원 정보 조회가 응답하지 않으면 로그인 화면에서 무한 대기

- 발견: W4 D2 / QA-S04-b2 / 인증 callback
- 데이터: 로그인 이전 목적지 /faq, 회원 역할 RPC 무응답
- 재현율: 설정 3/3. 회귀: SEL-08.

**절차**: /faq를 목적지로 로그인한다. 회원 조회 응답을 보류한다. 충분히 기다린 후 재시도 안내와 목적지를 확인한다.

**기대**: 정해진 대기 후 재로그인 안내가 표시되고 /faq가 보존된다. **실제**: 로딩만 남고 사용자가 탈출 경로를 찾기 어려웠다.

**분석·조치**: 미완료 인증 상태를 종료하는 제한 시간이 없었다. 30초 복구와 재로그인 진입, 목적지 보존을 추가했다.

**처리 이력**: W4 D2 New, W4 D3 Resolved, W4 D4 Retest→Closed. 늦은 정상 응답·미인증·정상 인증 복귀도 회귀했다.

## SIM-BUG-006 수수료 정책 변경 후 기존 수거의 정산 예상액 변동

- 발견: W5 D1 / QA-S05-b1 / 판매자 정산·관리자 정산
- 데이터: 정책 전 수거A와 새 정책 수거B, 판매가10000원, A의 기존 요율40%
- 재현율: 설정 2/2. 회귀: TC-033·034, DB 통합 수동 묶음.

**절차**: A의 예상 정산액을 기록한다. 신규 정책을 적용한다. A·B를 동일 가격으로 판매하고 예상 정산액을 조회한다.

**기대**: A는 기존40%로6000원, B는 새45%로5500원이다. **실제**: 두 건 모두5500원으로 계산되어 A의 약정 요율이 바뀌었다.

**영향**: 기존 판매자의 정산금액이 달라지는 P0 결함이다. **분석·조치**: 현재 정책으로 재계산하던 조회를 수거별 정책 스냅샷 기준으로 변경했다. 과거 정책 없는 행의 호환 경로도 검토했다.

**처리 이력**: W5 D1 New→Triaged, W5 D2 Resolved, W5 D3 Retest→Closed. A·B, 9999·10000·10001원, 과거 호환 건을 재확인했다. 이 문서는 실제 정산 데이터 수정이나 마이그레이션을 의미하지 않는다.

## SIM-BUG-007 문의 재시도마다 새 참조번호가 생성되어 중복 접수

- 발견: W5 D1 / QA-S05-b1 / B2B 문의
- 데이터: 동일 문의, 첫 큐잉 요청은 저장 후 응답 오류, 재시도 성공
- 재현율: 설정 3/3. 회귀: API-B2B-18 및 호출 원문 비교.

**절차**: 정상 문의를 보낸다. 첫 응답 실패를 주입한다. 두 번의 referenceId와 큐 레코드를 비교한다.

**기대**: 동일 참조번호를 재사용하고 DB 중복 방어로 접수1건이다. **실제**: 재시도 루프에서 새 번호가 발급되어 운영 문의가 두 건으로 들어왔다.

**분석·조치**: 참조번호 생성을 재시도 바깥으로 이동하고 참조번호별 멱등 처리를 확인했다.

**처리 이력**: W5 D1 New, W5 D2 Resolved, W5 D2 Retest→Closed. 503→200, 503→503, 403(재시도 없음)을 확인했다. 현재 로컬 자동화는 재시도 호출과 참조번호 보존을 검증하며 실제 DB 큐 중복 방지는 통합 검증 범위다.

## SIM-BUG-008 15MiB를 1byte 초과한 파일이 15.0MB로 안내됨

- 발견: W5 D3 / QA-S05-b3 / 관리자 이미지 업로드
- 데이터: PNG 메타데이터15728641bytes, 상한15728640bytes
- 재현율: 설정 3/3. 관련: TC-029·030, 기존 IMG 경계 자동화.

**절차**: 초과 파일을 선택한다. 업로드 차단 여부와 오류 문구의 현재 용량을 확인한다.

**기대**: 제한을 초과했음을 이해할 수 있는 표기다. **실제**: 업로드는 정상 차단되지만 현재 크기15.0MB가 제한15MB와 같아 보였다.

**분석**: 현재 용량을 소수 첫째 자리로 반올림했다. **대안**: 초과 안내에서는 올림·추가 자릿수·byte 표기 중 하나로 경계를 설명한다.

**처리 이력**: W5 D3 New→Triaged, W6 D1 Deferred. 기능적 차단과 데이터 보호는 정상이고 운영자가 더 작은 파일을 사용할 수 있어 후속 릴리스로 이관했다. 후속 담당 FE, 재검증 조건은 상한±1byte와 일반 대용량 파일의 안내 문구 확인이다. Closed로 집계하지 않는다.

# BR-IMG-001 · 제한 초과 파일의 15.0MB 표기

| 항목 | 내용 |
|---|---|
| 기록일 | 2026-10-24 |
| 상태 | OPEN · 표기 개선 제안 |
| 심각도 / 우선순위 | Minor / P3 제안 (팀 합의 전) |
| 연결 TC | IMG-03 |
| 환경 | 현재 adminImageUpload.js, Node 함수 검증; 파일 메타데이터와 저장소 응답 대체 |
| 재현 입력 | image/png, 15 × 1024 × 1024 + 1 = 15,728,641바이트 |

## 재현

1. 위 입력으로 `uploadImageToBucket('inspection-images', file, 'boundary')` 호출.
2. 반환된 오류 메시지와 저장소 호출 수 확인.

**실제:** `이미지는 한 장당 15MB 이하여야 합니다. (15.0MB)` 표시. 업로드는 정상 차단하며 저장소 호출은 0회.

**제안하는 기대:** 한도를 초과한 파일임을 명확히 안내. 예: `15MB를 초과한 이미지입니다. 파일 크기를 줄여 주세요.` 이는 이번 검토의 UX 기준이며 기존 명세의 문구 요구사항은 아님.

**영향:** 숫자가 제한과 같아 보이므로, 운영자가 거절 이유를 이해하기 어려움. 용량 제한 우회나 실제 업로드 실패 정책 오류가 아님.

**원인:** 비교는 정확한 바이트 수로 하지만 표시에서 `toFixed(1)`로 반올림함. 소수 첫째 자리까지는 15.0으로 표시됨.

**확인 근거:** `qa/results/results.json`의 IMG-03과 observations, `apps/admin-web/src/lib/adminImageUpload.js`의 validateImageFile. 현 시점 수정·재검증 완료로 표시하지 않음.

**수정 후 확인 항목:** 경계 아래/일치/초과 3건 재실행; 초과 안내 문구의 의미 확인; 정상 허용 및 전송 전 차단 유지.

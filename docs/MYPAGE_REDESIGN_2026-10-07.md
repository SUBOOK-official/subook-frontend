# 마이페이지 거래 내역 개편 — 2026-10-07

## 범위와 방향

P1 마이페이지의 구매·판매·정산 내역을 실제 회원 화면과 로그인 없는 데모에 함께 적용한다. 주문과 수거를 하나의 단위로 읽고, 자세한 내역은 필요한 순간 펼치는 구성이다. 흰 바탕, 얇은 구분선, 기존 수북 남색과 글자 크기로 정보의 우선순위를 나눴다.

- 구매: 주문별 상품 묶음, 한 번만 노출하는 처리 버튼, 상품명·주문번호 검색, 입금대기와 취소·부분환불 필터. 결제 상세와 입금 계좌는 펼쳐서 확인한다.
- 판매: 맡긴 교재 / 판매중 / 판매완료 요약, 수거별 접힌 목록, 검수 결과 바로가기, 검색과 상태 필터. 판매불가 교재가 일부 포함된 수거도 찾을 수 있다.
- 정산: 받을 정산금과 다음 입금일을 먼저 표시한다. 예정 / 입금완료 목록에서 판매금액, 수수료, 박스비, 실제 존재하는 일자를 펼쳐 본다.
- 모바일: 주요 내역을 앞에 둔 가로 메뉴와 필터. PC는 기존 사이드바를 간결하게 정리했다. 리뷰 안내는 구매 내역 아래에만 배치한다.

## 검토에서 확인해 수정한 문제

| 문제 | 변경 |
| --- | --- |
| 주문·수거 20건, 정산 50건 이후 미조회 | 기존 읽기 RPC를 빈 페이지까지 호출하고 화면은 더 보기로 나눔. 서버 제한, 중복 응답, 중간 실패도 검사 |
| `books.settled`를 입금 완료로 표시 | shared-domain 정의에 따라 판매완료로 표시. 입금 여부는 정산 내역에서 확인 |
| 수거 전체 상태·색상으로 책 수량 추정 | 교재별 상태로 집계. 재고가 없는 수거는 판매완료, 전부 폐기되면 판매불가 |
| 수거 취소가 판매불가로 분류됨 | 취소 상태·필터를 분리하고 맡긴 교재 수량에서 제외 |
| 부분환불·환불 접수 주문을 찾기 어려움 | 취소·환불 필터에 포함하고 선택한 교재에만 접수 상태 표시 |
| 환불 접수 후 반품 조회가 비었을 때 구매확정 노출 | 주문의 환불 접수 정보와 남은 미환불 교재도 확인 |
| 조회 실패가 빈 내역 또는 캐시처럼 보임 | 오류·재시도 화면으로 구분. 정상 빈 응답에는 최근 수거 fallback을 섞지 않음 |
| 잘못된 주문 날짜가 목록에서 사라짐 | 날짜 확인 중으로 유지 |
| 교재마다 반복되는 주문 행동과 불필요한 배송 조회 | 주문별 한 번만 표시. 운송장 있을 때 배송 조회 노출 |

도메인 의미는 `packages/shared-domain/src/status.js`와 backend의 수거·주문·정산 RPC 및 수수료 migration을 대조했다. DB, RLS, 결제 승인, 정산 계산식은 변경하지 않았다.

## 검증

- public 테스트 307개 통과. 데모의 실제 회원/DB 격리, 환불 대상, 조회 실패, 151건 이력, 서버 페이지 제한, 중복 페이지 회귀 검사 포함.
- frontend 전체 lint(public / mobile / admin), public production build 통과.
- 브라우저: PC 기본 뷰포트와 모바일 390px / 320px 확인. 모바일 페이지 가로 넘침 없음. 콘솔 오류·경고 없음.
- 구매 상세의 쿠폰·포인트·배송비 합계, 검색·검색 결과 없음·복귀, 복수 상품 주문의 구매확정, 한 권만 환불 접수, 수거 취소, 검수 결과 펼침, 정산 공제 상세, 입금완료 탭, 계좌 관리 이동, 샘플 초기화 확인.
- 실제 결제·환불·정산 실행은 수행하지 않았다. 변경된 UI 행동은 격리된 데모로 검증했고, 실제 RPC 읽기 경로는 현재 SQL 계약과 가짜 응답을 주입한 서비스 테스트로 검증했다.

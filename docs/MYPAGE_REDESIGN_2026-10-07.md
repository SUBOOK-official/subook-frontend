# 마이페이지 거래 내역 개편 — 2026-10-07

## 범위와 방향

P1 마이페이지의 구매·판매·정산 내역을 실제 회원 화면과 로그인 없는 데모에 함께 적용한다. 주문과 수거를 하나의 단위로 읽고, 자세한 내역은 필요한 순간 펼치는 구성이다. 흰 바탕, 얇은 구분선, 기존 수북 남색과 글자 크기로 정보의 우선순위를 나눴다.

- 구매: 주문별 상품 묶음, 한 번만 노출하는 처리 버튼, 상품명·주문번호 검색, 입금대기와 취소·부분환불 필터. 결제 상세와 입금 계좌는 펼쳐서 확인한다.
- 판매: 맡긴 교재 / 판매중 / 판매완료 요약, 수거별 접힌 목록, 검색과 상태 필터. 같은 날 운영 결정으로 판매불가 전용 안내와 사유 표시는 제거했다(아래 참조).
- 정산: 받을 정산금과 다음 입금일을 먼저 표시한다. 예정 / 입금완료 목록에서 판매금액, 수수료, 박스비, 실제 존재하는 일자를 펼쳐 본다.
- 모바일: 주요 내역을 앞에 둔 가로 메뉴와 필터. PC는 기존 사이드바를 간결하게 정리했다. 리뷰 안내는 구매 내역 아래에만 배치한다.

## 확인 링크

### 2026-10-07 후속 운영 결정: 폐기 사유 입력 제거

운영자는 현장에서 판매할 수 없는 교재를 자체 폐기하며 별도 사유를 작성하지 않는다. 이에 따라 마이페이지의 판매불가 배너·전용 필터·사유/사진/이의신청을 제거했다. 같은 날 후속 요청에 따라 ‘폐기’ 상태도 숨기고 해당 교재를 목록·검색·표시 권수에서 제외했다. 폐기 교재만 있는 수거도 판매 목록에서는 숨긴다. 실제 이력은 삭제하지 않는다.

어드민 검수 등록·재고 폐기·수거 상세의 단건/일괄 폐기에서 사유를 요구하지 않는다. 기존 데이터·내부 폐기 상태·진행 중인 주문의 폐기 방지는 보존한다. 서버의 신규 검수 RPC에서도 사유 필수 검증만 제거한다. DB 회귀 검사에서 익명/일반 회원 차단·중복 요청 방지·기존 기록 보존·판매용 교재 필수 검증을 확인했다. public 307개, admin 149개, DB 5개 테스트와 전체 lint·public/admin 빌드 통과.

브라우저에서 실제 검수 편집 컴포넌트와 확인 모달을 임시 하네스로 렌더링해 사유 입력 제거·확인 버튼 활성화를 확인했다. 운영 재고는 테스트로 폐기하지 않았다. 서버 migration `20261007031659`는 [공식 CLI 문서](https://supabase.com/docs/reference/cli/supabase-db-push)에 따라 별도 workdir에서 기존 무관한 미추적 migration을 제외하고 dry-run·push·적용 이력 확인을 마쳤다.

### 판매 교재 썸네일·옵션·상품 이동

- 판매 교재의 등급 표시는 제거하고 썸네일, 교재명, 옵션, 판매가, 상태 순으로 표시한다. 옵션이 없으면 ‘기본 구성’, 표지가 없거나 로딩에 실패하면 교재 아이콘을 표시한다.
- 썸네일·제목·옵션·가격 영역을 누르면 연결된 상품 상세로 이동한다. 아직 공개되지 않았거나 상세 페이지에서 조회할 수 없는 상품은 링크를 만들지 않는다.
- `get_my_pickup_requests`의 기존 두 교재 경로(신규/병합·레거시)에 상품 ID·표지 정보만 추가한다. 상세 페이지 공개 조건은 현행 `get_public_store_product_detail`과 동일하다. 회원 본인 이력 조회 조건과 권한은 보존한다.
- 데모 v4의 판매중 수거는 실제 공개 교재 세 종의 표지·상품 페이지를 예시로 연결한다. 데모 내 거래·가격은 예시이며 상품 링크를 따라가면 일반 스토어 화면이다.
- public 테스트 312개·격리 PostgreSQL 4개·전체 lint·public build 통과. 브라우저 PC 1280px·모바일 320px, 이미지 로딩, 등급·폐기 노출 없음, 옵션 검색, 실제 상품 상세 이동, 콘솔 오류 없음 확인.

- 아직 검수 중인 수거는 먼저 등록된 교재가 모두 폐기여도 진행 안내를 유지한다. 검수 완료 후의 폐기 제외 기준과 기존 상품 링크·옵션은 유지한다.
